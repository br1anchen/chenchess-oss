## Findings considered and rejected

- Keep the old `CI` workflow but change it to `workflow_dispatch`: rejected
  because the requested end state reserves GitHub Actions for manual deployment,
  and the existing local release proof already owns the credential-free gate.
- Install a Git `pre-push` hook: rejected because Jujutsu deliberately does not
  invoke it. A repository-local `jj checked-push` alias is available as an
  optional convenience, but cannot make the proof unavoidable.
- Disable GitHub Actions at repository level: rejected because the manual Maia
  runtime publication workflow still needs Actions and `GITHUB_TOKEN` package
  write access.
- Reproduce the hosted macOS/Linux/Windows matrix locally on every sync:
  rejected for this migration. The supported packaged runtime is Apple Silicon,
  the existing release proof already runs all behavior gates locally, and exact
  Windows parity would require a separate native or cross-toolchain project.
  Plan 001 makes the reduced portability guarantee explicit instead of implying
  equivalent coverage.
- Add a repository push wrapper: rejected because transport and authentication
  are environment-specific. The repository owns the proof, while Jujutsu owns
  the push using the developer's configured remote.
- Add a separate `ci:local` package alias: rejected as redundant. The existing
  `bun run release:proof` command is already the domain-appropriate full gate.
- Globally remove `com.apple.provenance` or disable Gatekeeper: rejected because
  repository performance work must not weaken host execution policy. Plan 003
  removes redundant executable copies and documents the host-policy boundary.
- Drop check, lint, build, or test categories from `release:proof`: rejected
  because ADR 0022 makes the complete credential-free proof the authoritative
  local CI gate.
- Serialize the entire Turbo graph without a benchmark: rejected because it can
  replace contention with the sum of every task's wall time. Plan 003 requires
  a measured follow-up only if Cargo concurrency remains dominant afterward.
